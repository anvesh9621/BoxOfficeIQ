## cinema_attendance

**Purpose:** Core fact table. Each row represents the attendance at a specific theatre on a specific date.  
**Source:** Synthetic data generated by `ml/pipeline/download_data.py`, loaded from `ml/data/raw/cinema_attendance.csv`.  
**Primary Key:** `(theatre_id, date)`

| Column | SQL Type | Python dtype | Description | Example Value | Valid Range / Notes |
|---|---|---|---|---|---|
| `id` | SERIAL PRIMARY KEY | int | Auto-increment surrogate key | 1 | Positive integer |
| `date` | DATE NOT NULL | datetime64 | Calendar date of observation | `2023-07-15` | 2022-01-01 to 2024-12-31 |
| `theatre_id` | VARCHAR(10) NOT NULL | str | Unique theatre identifier | `T001` | T001–T015 |
| `movie_id` | VARCHAR(10) | str | Movie screened that day (may be NULL if data unavailable) | `M012` | M001–M050, nullable |
| `audience_count` | INTEGER NOT NULL | int | Total number of tickets sold / attendees on this date | 342 | ≥ 0, typically 50–1200 |
| `online_bookings` | INTEGER | int | Number of tickets booked online (app/web) | 205 | ≥ 0, ≤ audience_count |
| `offline_bookings` | INTEGER | int | Walk-in and box-office ticket sales | 137 | ≥ 0, ≤ audience_count |
| `ticket_price` | FLOAT | float | Average ticket price in INR for that day | 220.50 | > 0, typically 100–600 |
| `show_count` | INTEGER | int | Number of screenings held that day at the theatre | 4 | 1–8 |
| `created_at` | TIMESTAMP | datetime | Row insertion timestamp | `2024-01-15T10:30:00` | Auto-set by DB default |

**Constraints:**
- `CHECK (audience_count >= 0)`
- `CHECK (online_bookings + offline_bookings <= audience_count + 1)` *(allows rounding)*
- `UNIQUE (theatre_id, date)`
- `FOREIGN KEY (theatre_id) REFERENCES theatre_info(theatre_id)`

**Indexes:**
- `idx_attendance_date` on `(date)`
- `idx_attendance_theatre_date` on `(theatre_id, date)` *(covering index for time-series queries)*

## Feature Engineering Reference

Engineered features are created by `ml/pipeline/feature_engineering.py` and stored in `ml/data/processed/features.csv`.

> **Data leakage guarantee:** All lag and rolling features are computed using strictly historical data only. For a row with date `d` and theatre `t`, only rows where `date < d AND theatre_id = t` are used in the computation.

### Temporal Features

| Feature Name | Formula / Method | Purpose | Example Value |
|---|---|---|---|
| `day_of_week` | `date.dayofweek` (0=Monday, 6=Sunday) | Capture weekly seasonality | `5` (Saturday) |
| `is_weekend` | `1 if day_of_week >= 5 else 0` | Binary weekend indicator | `1` |
| `month` | `date.month` (1–12) | Capture monthly/seasonal trends | `7` (July) |
| `day_of_month` | `date.day` (1–31) | Payday / month-start effects | `15` |
| `week_of_year` | `date.isocalendar().week` (1–53) | 52-week cyclical pattern | `28` |
| `quarter` | `date.quarter` (1–4) | Quarterly seasonality | `3` (Q3) |
| `is_holiday` | Hardcoded lookup of Indian public holidays | Holiday attendance spikes | `1` (Republic Day) |
| `days_since_start` | `(date - 2022-01-01).days` | Long-term trend / time index | `365` |

**Indian Holidays included (2022–2024):**
Republic Day (Jan 26), Holi (variable), Good Friday (variable), Eid al-Fitr (variable), Independence Day (Aug 15), Dussehra (variable), Diwali (variable), Christmas (Dec 25), New Year's Day (Jan 1), and 10+ others.

### Lag Features (Per-Theatre)

| Feature Name | Formula | Purpose | Example Value |
|---|---|---|---|
| `lag_1` | `audience_count` shifted 1 day for same theatre | Yesterday's attendance as predictor | `280` |
| `lag_7` | `audience_count` shifted 7 days for same theatre | Same day last week (captures weekly pattern) | `310` |
| `lag_14` | `audience_count` shifted 14 days for same theatre | Bi-weekly reference point | `295` |

**Note:** Rows where insufficient history exists (first 14 days per theatre) have NaN lag values and are **dropped** before training.

### Rolling Window Features (Per-Theatre)

| Feature Name | Formula | Purpose | Example Value |
|---|---|---|---|
| `rolling_mean_7` | `mean(audience_count[d-7 : d-1])` for same theatre | Short-term trend indicator | `297.4` |
| `rolling_mean_14` | `mean(audience_count[d-14 : d-1])` for same theatre | Medium-term trend baseline | `284.1` |
| `rolling_std_7` | `std(audience_count[d-7 : d-1])` for same theatre | Volatility / uncertainty signal | `42.3` |

All rolling windows use `min_periods=1` during the warm-up period but rows with fewer than 7 observations are excluded from training.

### Theatre Encoding

| Feature Name | Formula | Purpose | Example Value |
|---|---|---|---|
| `theatre_type_encoded` | Label encoded: Multiplex=0, SingleScreen=1, IMAX=2, DriveIn=3 | Theatre-class baseline capacity | `0` (Multiplex) |
| `theatre_id_encoded` | Label encoded integer (0–14) | Per-theatre fixed effect | `4` |

### Full Feature Vector

The final training feature matrix contains **18 features** in this order:

```
['day_of_week', 'is_weekend', 'month', 'day_of_month', 'week_of_year',
 'quarter', 'is_holiday', 'days_since_start', 'lag_1', 'lag_7', 'lag_14',
 'rolling_mean_7', 'rolling_mean_14', 'rolling_std_7',
 'theatre_type_encoded', 'theatre_id_encoded',
 'ticket_price', 'show_count']
```

This list is saved to `ml/data/processed/feature_names.json` for reproducibility.
